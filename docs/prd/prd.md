# PRD — 마케팅 허브 웹

입력: `docs/project-init.md`. 상태: draft. demo 프로젝트. `(가정)` = 원문에 없어 정한 값, 또는 원문이 `(가정)` 으로 표시한 값. 가정 ID 는 §6. 입력 원문의 `(가정)` 은 8개(project-init.md:15·16·17·23·24·38·54 와 §3-1 일정)이며 A-01·A-02·A-13~A-15 와 §2-2 제외 표로 이어진다.

## 1. 목표

- 한 문장: 통신사별 LLM 서비스 홍보·이벤트를 한 페이지(허브)에서 노출하고 방문자의 이벤트 응모를 받는다.
- 측정 대상: 허브 방문 규모(M-01), 상세 조회 대비 응모 완료 비율(M-02), 응모 완료까지 걸리는 시간(M-03).

## 2. 범위

### 2-1. 포함 (가정)

### 2-4. 지표 집계·보관 (P-07 상세)

원시 로그를 90일 뒤 지우면 고유 방문자 수와 중앙값은 나중에 다시 계산할 수 없다(월·일 값을 더해도 고유 수·중앙값이 안 나온다). 그래서 **삭제 전에 지표 값을 확정해 저장**한다. 아래 3종 모두 방문자 ID 를 담지 않는다 (가정, A-23).

| 산출물 | 집계 단위 | 담는 값 | 집계 시점 | 쓰는 지표 |
|---|---|---|---|---|
| 일 집계 | 일 × 이벤트 ID × 이벤트 종류(`page_view`·`form_open`·`apply_complete`) | 건수, 그 날 안의 고유 방문자 수 | 매일 1회, 다음 날 02:00(가정)에 전날 수집분 | 일 추이·검산(M-01~M-03 의 값은 아래 2종) |
| 월 방문자 확정 | 월 | SCR-01·SCR-02 진입 고유 방문자 수 | 월 종료 다음 날 집계 작업에서 확정 | M-01 |
| 이벤트 확정 집계 | 이벤트 ID | SCR-02 `page_view` 고유 방문자 수, SCR-04 `apply_complete` 고유 방문자 수, 완료 건별 소요 시간(초) 값 목록(방문자 ID 없음) | 이벤트 종료가 확정된 다음 날 확정. 진행 중에는 매일 잠정값을 덮어쓰고 확정 값이 아니다 | M-02(두 고유 수의 비), M-03(값 목록의 중앙값, 이벤트별 목록을 합쳐 계산) |

순서(위에서 아래로, 앞 단계가 끝나야 다음):
1. 수집 — 원시 로그 기록. 운영 관리자 세션은 수집하지 않는다(A-20).
2. 집계 — 일 집계, 월 방문자 확정, 이벤트 확정 집계를 위 시점에 실행하고 로그 구간마다 "집계 완료"를 표시한다.
3. 삭제 — 수집일 + 90일이 지난 로그 중 그 로그가 들어가는 일 집계·월 확정(·해당 이벤트의 확정)이 전부 완료 표시된 것만 삭제한다. 미완료면 삭제를 보류하고 집계를 재시도한다. 보류는 최대 7일(가정)이며 넘으면 집계 실패로 기록하고 삭제한다(지표 결손은 열린 점 3).
4. 전제 — 이벤트 확정 집계는 이벤트 시작부터 종료 확정 다음 날까지의 로그가 삭제 전에 남아 있어야 하므로 이벤트 기간 89일 이하를 전제한다 (가정, A-23).

## 4. 성공 지표 (가정)

지표 선택 자체가 원문의 `(가정)` 이다(원문 §1-1, A-15).

| ID | 지표 | 정의식 | 측정 위치 | 목표값 |
|---|---|---|---|---|

- 정합: M-01 → S-01·S-02 / M-02 → S-02·S-04 / M-03 → S-04. 지표 3개 모두 포함 범위 안의 화면에서 측정된다.

- 이벤트 이름과 수집 방식(자체 DB 기록 vs 외부 분석 도구)은 기획 단계에서 확정한다. 이름은 현재 가정값이다. 외부 도구를 쓰면 P-01 개인정보를 보내지 않는다 (가정). 수집한 로그의 집계·보관·파기는 P-07·§2-4.

## 7. 열린 점

1. 제외 범위에 "회원 가입·로그인" 이 있으나 운영 관리자 화면은 접근 통제가 필요하다. 단일 접근 코드 + 세션 한정 유지(A-10·A-16)로 임시 해소했다. 코드 입력 후 유지가 사실상 로그인인지에 대한 해석은 사람이 확정한다. 대체안(로그인으로 판정되면): S-08·SCR-05·P-05 를 이 PRD 에서 빼고(SCR-05 는 `(폐기)` 로 남김), S-05~S-07 의 접근 전제를 "앱 밖(배포 환경의 접근 제한)이 제공"으로 바꿔 제외 범위와 충돌하지 않게 한다 (가정).
2. 지표 목표값 3개 모두 미정. 착수 전 기준선 확보 또는 경영 판단 필요.
3. 90일 파기·집계의 실행 방식(예약 작업 등)은 개발 단계에서 정한다. 기준일(A-17), 원시 로그 보관 기간(A-18), 집계 시각·삭제 보류 7일·이벤트 기간 89일 전제(A-23)는 사람이 확정한다. 89일을 넘는 이벤트와 보류 한도 초과로 생기는 지표 결손의 처리는 미정.
4. 단계별 checker 검수 시간이 실제로 주 단위를 넘으면 7주가 늘어난다(A-19). 집계 작업 W-26 추가와 재배치(A-24)로 4~6주차 개발 작업이 겹친다. WBS 사람 게이트에서 확인한다.
