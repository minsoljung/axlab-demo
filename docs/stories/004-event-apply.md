# 004 이벤트 응모

- 화면: SCR-03, SCR-04

## Story
방문자로서 로그인 없이 이름과 휴대전화번호로 이벤트에 응모하고 싶다. 가입 절차 없이 바로 참여하기 위해서다. (S-04, A-01)

## AC
- AC-004-1: 진행 중 이벤트의 SCR-03 을 열면 입력 항목이 이름·휴대전화번호·개인정보 수집·이용 동의 체크 3개만 보인다 (P-01, A-04).
- AC-004-2: 이름·휴대전화번호를 입력하고 동의를 체크해 제출하면 SCR-04 로 이동하고 "응모 완료"가 보인다.
- AC-004-3: 이름·휴대전화번호를 입력하고 동의를 체크해 제출하면 그 이벤트의 응모 행이 1건 늘어난다.
- AC-004-4: 이름이 비어 있으면 SCR-03 에 "이름을 입력해 주세요"가 보이고 응모 행은 늘지 않는다.
- AC-004-5: 휴대전화번호에 숫자가 아닌 값("abc")을 넣어 제출하면 SCR-03 에 "휴대전화번호를 확인해 주세요"가 보이고 응모 행은 늘지 않는다.
- AC-004-6: 동의를 체크하지 않고 제출하면 SCR-03 에 "개인정보 수집·이용에 동의해 주세요"가 보이고 응모 행은 늘지 않는다.
- AC-004-7: 같은 이벤트에 이미 응모한 휴대전화번호로 다시 제출하면 SCR-03 에 "이미 응모한 번호입니다"가 보이고 응모 행은 늘지 않는다 (P-03, A-06).
- AC-004-8: 다른 이벤트에 응모한 휴대전화번호로 이 이벤트에 제출하면 SCR-04 로 이동한다 (P-03, A-06).
- AC-004-9: 종료된 이벤트의 SCR-03 주소로 들어가면 입력 폼 대신 "종료된 이벤트입니다"가 보인다 (P-04, A-08).
- AC-004-10: 종료된 이벤트에 응모 제출 요청을 보내면 응모 행은 늘지 않는다 (P-04).
- AC-004-11: 제출 응답이 지연되는 동안 SCR-03 의 제출 버튼은 비활성 상태이다.
- AC-004-12: 제출 요청이 서버 오류로 실패하면 SCR-03 에 "응모에 실패했습니다"가 보이고 응모 행은 늘지 않는다.
- AC-004-13: SCR-03 에서 상세로 돌아가는 동작을 하면 SCR-02 로 이동한다.
- AC-004-14: SCR-04 에서 목록으로 가는 동작을 하면 SCR-01 로 이동한다.
- AC-004-15: SCR-04 에서 이벤트 상세로 가는 동작을 하면 SCR-02 로 이동한다.

## e2e 비대상 (단위·통합 테스트 대상)
- M-02 이벤트당 응모 전환율 · M-03 응모 완료까지 걸리는 시간: `form_open`·`apply_complete` 이벤트 수집과 집계·중앙값 계산(A-11)은 단위·통합 테스트로 판정한다.
- P-07 지표 이벤트·익명 방문자 ID 파기: 원시 로그 90일 삭제, 집계 완료분만 삭제, 삭제 보류 7일, 집계 3종 보관(A-18·A-23), `apply_complete` 에 응모 식별자·이름·휴대전화번호가 없는지는 단위·통합 테스트로 판정한다. 구현 W-16·W-26, 검증 W-20.
- P-02 응모 개인정보 파기: 기준일 = min(종료 예정일, 수동 종료 처리일) + 90일 삭제, 기준일 3사례(prd.md §2-3a), 종료 확정 시 기준일 고정(A-05·A-17·A-21)은 시간 경과가 필요해 단위·통합 테스트로 판정한다. 구현 W-16, 검증 W-20.
