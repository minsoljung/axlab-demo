# 008 운영자 접근 통제

- 화면: SCR-05, SCR-06, SCR-07

## Story
운영 관리자로서 접근 코드를 확인한 세션에서만 관리자 화면과 기능을 쓰고 싶다. 계정 없이도 관리자 기능을 외부인으로부터 막기 위해서다. (S-08, A-10)

## AC
- AC-008-1: 관리자 주소로 들어가면 SCR-05 에 접근 코드 입력란과 확인 버튼이 보인다.
- AC-008-2: 올바른 접근 코드를 입력해 확인하면 SCR-06 으로 이동한다.
- AC-008-3: 틀린 접근 코드를 입력해 확인하면 SCR-05 에 "접근 코드가 올바르지 않습니다"가 보이고 SCR-05 에 머문다.
- AC-008-4: 접근 코드를 확인하지 않은(미확인) 세션에서 SCR-06 주소로 직접 들어가면 SCR-05 로 이동하고 SCR-06 의 이벤트 목록은 보이지 않는다 (A-16).
- AC-008-5: 접근 코드를 확인하지 않은(미확인) 세션에서 SCR-07 주소로 직접 들어가면 SCR-05 로 이동하고 SCR-07 의 입력 폼은 보이지 않는다 (A-16).
- AC-008-6: 접근 코드를 확인하지 않은 세션에서 이벤트 등록 요청을 보내면 요청이 거부되고 이벤트 행은 늘지 않는다 (P-05).
- AC-008-7: 접근 코드를 확인하지 않은 세션에서 이벤트 수정 요청을 보내면 요청이 거부되고 저장된 값은 그대로이다 (P-05).
- AC-008-8: 접근 코드를 확인하지 않은 세션에서 이벤트 종료 요청을 보내면 요청이 거부되고 그 이벤트는 진행 중 상태 그대로이다 (P-05).
- AC-008-9: 접근 코드를 확인한 뒤 마지막 요청으로부터 30분이 지나 SCR-06 을 요청하면 SCR-05 로 이동한다 (A-22).
- AC-008-10: 접근 코드를 확인한 뒤 계속 사용하더라도 8시간이 지나 SCR-06 을 요청하면 SCR-05 로 이동한다 (A-22).
- AC-008-11: 접근 코드를 확인한 뒤 브라우저를 종료했다가 다시 열어 SCR-06 주소로 들어가면(세션이 없는 미확인 상태) SCR-05 로 이동한다 (A-16).
- AC-008-12: 접근 코드(환경변수)가 바뀐 뒤 기존 확인 세션에서 SCR-06 을 요청하면 SCR-05 로 이동한다 (A-22).
- AC-008-13: SCR-06 의 로그아웃 동작을 하면 SCR-05 로 이동한다 (A-22).
- AC-008-14: 로그아웃한 뒤 SCR-06 주소로 직접 들어가면 SCR-05 로 이동한다 (A-22).
- AC-008-15: 만료·접근 코드 변경·로그아웃으로 SCR-05 로 이동하면 SCR-05 에 "다시 접근 코드를 확인해 주세요"가 보인다 (A-16·A-22).
- AC-008-16: SCR-07 에서 저장 요청을 보낼 때 세션이 만료돼 있으면 SCR-05 로 이동하고 이벤트 행은 늘지 않는다 (P-05, A-22).
- AC-008-17: 만료로 SCR-05 에 이동한 뒤 접근 코드를 다시 확인하고 신규 등록용 SCR-07 을 열면 모든 입력란이 빈 값이다 (P-05, A-22).
- AC-008-18: SCR-06 에서 방문자 화면으로 가는 동작을 하면 SCR-01 로 이동한다.
- AC-008-19: 만료로 SCR-05 에 이동한 뒤 접근 코드를 다시 확인하고 기존 이벤트의 수정용 SCR-07 을 열면 입력란에 서버에 저장된 값이 채워져 있다 (AC-006-1 과 같은 값이며 만료 전에 저장하지 않은 입력은 없다) (A-22).
- AC-008-20: 접근 코드를 확인하지 않은(미확인) 세션이 SCR-06 또는 SCR-07 주소로 직접 들어가 SCR-05 로 이동하면 SCR-05 에 "다시 접근 코드를 확인해 주세요"가 보인다 (A-16, SCR-05 디자인 명세와 같은 문구).

(가정) 미확인 직접 진입에도 만료·변경·로그아웃과 같은 안내 문구 하나를 쓴다(이유별 문구 없음). 관리자 주소로 처음 들어오는 경우(AC-008-1)는 안내가 없다. 문구는 "다시"가 처음 진입자에게 어색할 수 있어 기획·디자인 확정 대상이다.
